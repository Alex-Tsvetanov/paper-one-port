\Title{One Port for Many Protocols: The Cost, Robustness and Mechanism of First-Bytes
Demultiplexing}

\Author{Alex I. Tsvetanov \orcidA{}}

\AuthorNames{Alex I. Tsvetanov}

\address[1]{Faculty of Computer Systems and Technologies, Technical University of Sofia,

% With the class option oneauthor, mdpi.cls prints no correspondence line, so the e-mail is in
% the address above as well.
\corres{Correspondence: atsvetanov@tu-sofia.bg}

\abstract{Servers usually listen on one port per protocol; one listener can serve every protocol by
reading each connection's first bytes, at an unmeasured cost. We built \oneport, a minimal
C++23 server for HTTP/1.1, h2c, TLS, SSH and MQTT on epoll, io\_uring and I/O completion ports. We
compared one listener with one port per protocol on Linux and Windows. Hypotheses, tests and rules
were frozen before any server code existed. Tests used bootstrap intervals and exact sign tests
under Holm's procedure. Under load of one protocol, one-port mode was equivalent
within \MarginLow{} to \MarginHigh{} in \CostPassed{} of the \CostHolm{} tested cost cells. All three
cost tests passed for HTTP/1.1, TLS and MQTT on Linux and HTTP/1.1 and TLS on Windows. On Linux,
h2c's latency at a fixed load was not shown equivalent, once as a measured cost. The detector
decided all \HardcaseRuns{} hard-case runs as specified. By the frozen footprint test, nginx,
HAProxy, Envoy and hyper-util held at least \FootprintMargin{} times the server's counted footprint
per pending connection; sslh-ev held less. A mixed-protocol load starved new connections on the
io\_uring backend in both modes. So, for this server, one listener served HTTP/1.1, TLS and MQTT
there at no measurable cost.}

\keyword{protocol detection; port unification; first-bytes demultiplexing; TLS; HTTP/2; MQTT;
PROXY protocol; epoll; io\_uring; I/O completion ports; equivalence testing; benchmarking}
